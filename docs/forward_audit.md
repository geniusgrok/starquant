## 剩余风险

- 没有 5 秒成交带。分钟内部仍是开高低收四点。前向权益路径比历史测量更粗。
- 进程不在时，通道出场和一半峰值平仓不会执行。停机保护只有最后一次确认的止损和灾备止盈。
- 维护保证金率仍是回放里的一张表，前向强平距离来自当次快照，两者不是同一条数据。
- 用户流字段和 `/private/ws` 路径对照的是 binance SDK 3.6.0、一份 2025-12-11 的公开报文，以及 unicorn-binance-websocket-api 对 2026-04-23 变更的实现。官方 HTML 页面在本机仍被脚本墙挡住。真实 Demo 套接字没有连上。
- 本机地区限制和缺少密钥，使官方 Demo 与生产的只读核对都没有发生。
- 资金费 2026-09-01 00:00 UTC 未验证，2026-09 其余槽位是溢价估算。
- 工程上可以启动，不等于 150% 年化或回撤低于 50% 已经达到。一个月 Demo 盈利也不能外推。

### S14：策略与内核的逐分钟对照

方法：`tests/test_kernel_parity.py` 用同一串合成分钟，让回放内核（`frontier.py` 的 `resume`，`defer=1`）和前向的 `policy` + `runner` 各跑一遍，逐事件比较方向、数量、止损价，并覆盖入场、加仓、离场、止损、反手、重启往返（Store 存取）和回撤锁。发现并已修的四处：

1. 加仓名义上限：前向没有按研究口径的名义上限收紧加仓量，新增 `research_notional`。
2. 反手不受门控：非整点、冷却期或回撤锁下也会反手开仓，现在只有 `may_open` 时才开新仓，否则只是离场。
3. 加仓后的保本止损：内核加仓后止损上移到保本，前向漏了，现在补上。
4. 强平价夹紧：止损落在强平价外侧时内核夹紧，前向没有，新增 `clamp_to_liquidation`。

有意保留的差异：

- 定量价格：前向按信号收盘价算数量，内核按成交开盘价算，对照测试容忍 2% 相对误差。
- 一半峰值平仓：前向用分钟收盘时的不利极值，内核用分钟内路径。
- 止损成交：前向由交易所执行，内核按路径模型成交。
- 强平：前向用交易所给的强平价，内核用保证金模型。
