# BTCUSDT 账户（私人研究）

本文件说明模型、数据、账本和测量做不到的事。使用范围以仓库根目录的 [`LICENSE`](../LICENSE) 为准：只有版权人 geniusgrok 本人可以把它用于私人研究，禁止实盘，禁止他人复制或二次创作。当前结果和压力表在 [`PROJECT_STATE.md`](../PROJECT_STATE.md)，轮次在 [`measure_protocol.md`](measure_protocol.md)。

## 运行

```bash
python -m btc_perp --measure
```

先按仓库根目录的 README 装好环境。这会读取 `config/btc_account.yaml`，在本地 `data/` 上把 2020-01-01 00:00 UTC 到 2026-09-20 00:00 UTC（结束日不含，最后一根是 2026-09-19 23:59）走完，并把结果写入 `reports/btc_account_measure.json`。

测量本身就是一串手动会话。每一段新建一个 `Session`，时钟用 `ManualClock`，时长和轮询取配置里的 `session_seconds`（300 秒）和 `poll_seconds`（5 秒）。这一段的 `run` 返回之后，才构造下一段。同一个 `SimExchange` 留着仓位、止损和止盈。没有常驻进程。

一分钟行情要等这段时钟走完这一分钟才推进。5 秒一轮时，第 12 次轮询（时钟 55 秒，加上这一轮的 5 秒）才处理第一根分钟，不会在会话一开始就把这 5 分钟算完。持仓变化通过会话下单：平仓、加仓、同一分钟先平再开，以及只改止损止盈。模拟账户的数量必须和内核一致，否则测量直接失败。

不带 `--measure` 的 `python -m btc_perp` 只打印一句拒绝，然后退出。它不启动会话，也不下单。

`data/` 已被 `.gitignore` 排除。没有这些文件时，全样本测试会跳过。

## 模型

收盘价向上突破前 1008 根已完成小时的最高价就开多，向下突破前 1008 根的最低价就开空。多头在收盘跌破前 192 根小时的最低价时平掉，空头在收盘升破前 192 根小时的最高价时平掉。当前小时不进入通道。窗口根数不够时，该通道是无穷大或无穷小，不出信号。

入场和加仓只在每小时第 59 分钟。通道出场在任意一分钟的收盘都可以发生，并且不进入冷却，所以同一根分钟可以先平再开到另一边。

| 项 | 配置 | 含义 |
| --- | --- | --- |
| 初始止损 | `stop: 0.032` | 成交价的 3.2% |
| 移动止损 | `trail: 0.16` | 从持仓以来的极值回撤 16% |
| 收紧 | `ratchet_gain: 0.35`，`ratchet_trail: 0.07` | 浮盈达到 35% 之后，移动止损改成 7% |
| 加仓 | `add_step: 0.05`，`max_units: 3` | 沿有利方向每 5% 加一档，最多 3 个单位。加仓不使用 82% 缩量 |
| 单位风险 | `risk: 0.048` | 按止损距离，一档风险是当时权益的 4.8% |
| 名义上限 | `heat: 0.6` | 大约是当时权益的 3.75 倍（`heat / trail`）。价格逆向以后，名义/权益可以暂时更高 |
| 逐仓比例 | `iso_frac: 0.28` | 保证金上限是权益的 28%，再乘 20 倍，约 5.6 倍名义。热度先把名义限制在约 3.75 倍 |
| 缩量 | `entry_scale_below: 0.82`，`entry_scale: 0.5` | 收盘权益低于收盘峰值的 82% 时，新开仓风险用一半 |
| 收盘封锁 | `dd_flat: 0.47` | 收盘权益/峰值降到 0.53 或更低时，不开新仓，也不加仓。已有仓位还留着 |
| 一半峰值 | `flatten_ratio: 0.5` | 路径上的权益降到路径峰值的一半或更低时平仓。设成 0 就关掉 |
| 冷却 | `cooldown_hours: 6` | 止损或一半峰值平仓之后，6 小时内不再开仓、不加仓 |
| 远端止盈 | `take_profit_multiple: 10` | 只挂在测量用的模拟交易所上。回放不按这个价格出场 |

数量按 0.001 BTC 向下取整，名义低于 100 USDT 不开仓。开仓还留 2% 现金。20 倍名义上限 500 万 USDT。

同目录还有三组 zip，回放不把它们当第二套行情：

- `data/klines/`：99 个 BTCUSDT 1 分钟 zip，2020-01 至 2026-08 按月，2026-09-01 至 2026-09-19 按日。`npz` 由它们合成。`--measure` 读 `npz`。
- `data/funding/`：80 个官方资金费月文件，2020-01 至 2026-08，已写入 `funding.npz`（7,305 条）。最后一条官方时间是 2026-08-31 16:00:00.001 UTC。
- `data/premium/`：19 个 2026-09-01 至 2026-09-19 的 8 小时溢价 K 线。官方 9 月资金费月文件还没有，这 19 天用溢价近似：四价平均，加上夹在 ±0.0005 里的 `0.0001 − 平均`，再夹到 ±0.003。时间先加 8 小时再归到 8 小时整点，好让费率落在结算小时。缺 2026-09-01 00:00 UTC 那一档。删掉整个 9 月资金费，期末少 1,637 元。

`usdcny_frankfurter.json` 是 Frankfurter 的美元兑人民币，`base` 为 USD，日期从 2019-12-31 到 2026-09-18，共 1,722 天。2019-12-31 的中间价是 6.9615。某一分钟只用严格早于该日的最新中间价。

USDT 按美元折人民币，没有单独记脱锚。

## 账户规则

- 一个 BTCUSDT U 本位永续账户，起始 10,000 元人民币，中间不加钱。
- 单向、逐仓。引擎按 20 倍把保证金记成名义金额的 1/20。
- 可以做多，也可以做空。
- 维持保证金用 `btc_perp/costs.py` 里的 BTCUSDT 档位（名义 5 万以内 0.40%，25 万以内 0.50%，100 万以内 1.00%，500 万以内 2.50%，更高 5.00%）。这是公开发布的 125 倍档位表，不是实盘接口拉下来的。样本期内档位调整过，这里整段用一张表。强平价按强平时的名义再套一次档。
- 止损如果落在强平价外侧，就收到强平价再偏 0.1% 的位置，让止损留在强平之前。
- 资金费从钱包和逐仓保证金里扣。保证金余额等于逐仓保证金加浮盈浮亏；不够维持保证金时按当根开盘价平仓，这笔仓位的亏损不超过已付保证金。浮盈还盖得住资金费时，仓位继续留着。资金费把已付保证金扣成负数以后，再出现的价格亏损不再从钱包扣，也不会把这笔负数保证金记成收入。2026-09-28 这组全样本里，持仓期间的逐仓保证金最低约 107 USDT，没有出现负数；钱包最低约 1,431 USDT。

费率、杠杆和缩量常数定义在 `btc_perp/costs.py`。回放循环直接读这份常量里的手续费、滑点、换汇费和杠杆。YAML 里的同名副本必须相同，否则 `tests/test_btc_account.py` 失败。窗口、止损、`dd_flat`、`flatten_ratio`、开仓缩量和热度从 YAML 传入内核。

一半峰值的平仓：先解出权益恰好等于 `flatten_ratio × 路径峰值` 的价格；这一跳已经穿过该价格时，按这一跳的价格平。滑点用上一根已完成的分钟，和止损相同。成交记进止损次数，并进入冷却。价格止损更近时，先按价格止损成交。路径上先记下穿越时的权益，再按逐仓保证金上限结算，所以这笔回撤会留在最低比值里。

`take_profit_multiple` 挂在模拟交易所上：多头用成交价乘这个倍数，空头用成交价除以它。回放出场仍是移动止损、通道和一半峰值平仓。模拟撮合不会按这个止盈价成交。

## 测量口径

- 每根 1 分钟内部按四段价格走。阳线的顺序是开盘、最低、最高、收盘；阴线是开盘、最高、最低、收盘。止损在新极值出现后的下一段价格上可以成交。没有 5 秒成交明细，这个顺序是假设。把顺序对调之后，期末是 1,745,597 元，年化 115.62%，最低比值 0.526。
- 止损可能在这根分钟走完之前成交，冲击成本用上一根已经完成的分钟。收盘才发生的开仓、加仓和通道出场，用当根已经完成的分钟。一半峰值的平仓沿用止损的滑点。单笔名义超过该分钟成交额时，参与率按 1 封顶。
- 价格亏损和当次资金费加在一起，超过这笔逐仓保证金的部分不再从账户扣。
- 人民币汇率用上一个已经公布的 Frankfurter 日期。当天的中间价从当天 00:00 UTC 起还不知道，不能用来给当天的权益标价。

## 测量做不到的事

这些限制留在结果旁边。离线测试通过，不表示可以下单。

- 止损、通道出场和一半峰值平仓都由内核在假设路径上决定。会话发现内核仓位变了，再向 `SimExchange` 发一张镜像市价单。模拟交易所自己不根据价格去碰休息着的止损和止盈。进程在两段会话之间退出以后，也没有另一个程序盯着行情。
- 正式测量的模拟成交比例是 1。部分成交、迟到成交和「先平后开被剩余量挡住」只在合成测试里出现，没有一条部分成交的全样本经济结果。
- 706,752 段会话在同一个进程里首尾相接。这检查会话边界和内核是否一致，不检查断电、断网或交易所拒绝。
- 没有在真实账户上核对成交、保护替换、断线和迟到成交。`BinanceExchange.allowed` 固定返回假，`submit_market` 固定拒绝。
- 跳过 20% 会话的那一行说明：分钟不被步进时，止损也不会被检查。那一行的年化是 14.12%，最低比值 0.467。
