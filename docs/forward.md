# 前向账户操作与恢复

仅供版权人本人的 BTCUSDT U 本位永续账户。**DEMO_GO = NO_GO，SMALL_LIVE_GO = NO_GO**：原生执行尚无本人 Demo 开仓、条件保护实际触发、拒单与恢复回包、连续 30 天真实时间记录。新旧同向 close-all 保护及条件单父子回包仍需远端验收。以下说明当前命令和保护边界，不构成交易所撮合或实盘收益认证。

## 环境与配置

| 项 | Demo | 生产 |
| --- | --- | --- |
| REST | `https://demo-fapi.binance.com` | `https://fapi.binance.com` |
| 密钥 | `STARQUANT_DEMO_API_KEY` / `STARQUANT_DEMO_API_SECRET` | `STARQUANT_PROD_API_KEY` / `STARQUANT_PROD_API_SECRET` |
| 账户绑定 | 默认使用密钥指纹；换密钥须核验原状态 | `STARQUANT_ACCOUNT_UID` 必填，远端 UID 必须一致 |
| 默认状态目录 | `~/.local/state/starquant/demo/` | `~/.local/state/starquant/prod/` |

所有命令必须指定 `--environment`。程序不自动更改杠杆、单向持仓或逐仓模式；账户须符合 [config/btc_account.yaml](../config/btc_account.yaml)。默认开仓通道为 1008 个完整连续已完成小时（42 天），离场通道为 192 小时（8 天）；不足的窗口不能形成对应通道信号，存量保护、减仓及梯度加仓仍可能执行。开仓还须满足每小时最后一分钟的收盘门限。未完成分钟不产生信号，小时缺口、重复或错误格式会使通道无效。新增风险只用最新账户快照与不超过 30 秒的信号；补齐旧分钟只恢复记忆，不按当前价格执行旧入场。`check` 不拉取策略 K 线，不能证明预热完成。

生产新增风险须同时满足：`STARQUANT_ALLOW_PROD_ORDERS=yes`、正的 `--max-notional-usdt`、[limits.yaml](../config/limits.yaml) 四个字段均为正数，以及密钥权限明确允许合约、禁止提币和划转。命令行名义上限高于文件上限会被拒绝。UID 不明时拒绝账户写入；已确认 UID 的 `stop` / `flatten` 不依赖辅助权限元数据完整，但生产只减仓市价单仍要求订单开关开启。

| 限额 | 含义 |
| --- | --- |
| `capital_usdt` | 仓位计算使用的权益不超过此值 |
| `max_notional_usdt` | 名义敞口上限；还受命令行上限约束 |
| `max_daily_loss_usdt` | 相对 UTC 日首次有效权益观测，达到损失线后冻结新增风险，不自动清仓 |
| `max_unprotected_seconds` | 已核验归属仓位超过裸露预算时尝试只减仓 |

限额不保证最大累计亏损。止损可能跳空、滑点或执行失败，入场与保护建立不是原子操作。未提供 `--fx` 时峰值按 USDT 记录；正的 `--fx` 用于人民币换算，改变计价单位会换算既有峰值，不抹去亏损历史。`--poll-seconds` 只能设置为 1–5 秒；`session_seconds` 不控制前向运行时长。

## 命令

先核对账户和状态，再选择操作：

```bash
python -m btc_perp check --environment demo
python -m btc_perp run --environment demo --max-notional-usdt 200 --dry-run --once
```

`check` 和 `--dry-run` 不向交易所写入，仍读取真实账户并维护本地目录、锁、绑定与诊断记录。`run --once` 没有隐含的 dry-run；去掉 `--dry-run` 后会进行真实账户轮次并尝试安全停机。普通 `run` 连续轮询。

| 操作 | 命令与行为 |
| --- | --- |
| 运行 | `run --environment demo --max-notional-usdt 200`：持续执行前向轮次 |
| 停机 | `stop --environment demo`：撤销本程序的增仓挂单，保留实仓上已确认的止损与灾备止盈；空仓时清理自有保护 |
| 清仓 | `flatten --environment demo --once`：操作员明确请求只减仓平掉实际仓位 |
| 接管 | `takeover --environment demo --once`：在本地按当前实仓接管，持续冻结新增风险，不向交易所写入或建立保护；随后须通过 `run` 核验并补齐保护 |
| 解除请求 | `resume --environment demo`：只删除本环境的 stop / flatten 请求文件，不解除账户、资金或回撤冻结 |
| 核销意图 | `resolve --environment demo --client-id <编号> --yes`：操作员先核对，再由交易所明确确认原身份不存在；查询失败不放行 |
| 重新启用 | `rearm --environment demo --yes`：仅在空仓、无活动订单、无未决意图或未结算保护、历史覆盖已证明时执行，具体峰值处理见下文 |

表中命令均接在 `python -m btc_perp` 后。`stop` / `flatten` 会写带环境标识的请求文件；已有进程持锁时由运行进程处理，独立命令可能返回非零并提示请求已写入。两种请求同轮出现时优先清仓，运行进程处理后退出。请求至多等待当前轮次及下一次轮询间隔才开始处理。

成功的停机或清仓必须确认 `settled=true`，并核对 `remaining`。快照未知、活动外来订单、未知保护、未决子单或裸仓不能报完成。`run_state.json` 记录最终 `phase`、`exit_code` 与收尾剩余项；业务冻结、收尾未确认或中断返回非零，不能只凭进程退出判断安全。首次 SIGINT / SIGTERM 触发有界收尾，随后信号不会提前打断状态写入；强杀或断电不保证收尾。

进程停止后，本地移动止损、通道和权益出场不再计算，只剩最后确认的交易所止损与灾备止盈。需要平仓时使用明确的 `flatten`，核对实仓和订单回读。

## 状态与订单协议

`--state-dir` 必须为绝对路径，直接指定环境状态目录。`STARQUANT_STATE_DIR` 也必须为绝对路径，程序在其下加 `demo` / `prod`。启动输出环境、绑定身份和最终路径。源码目录变化不改变默认状态，仓库内旧状态不会自动迁移；迁移前核对账户、峰值、资金锁、未决意图和游标，保留完整原状态。

`account.sqlite` 保存策略记忆、账户绑定、峰值、流水游标和持久化订单意图；`environment` 标记环境。状态目录锁与固定在 `~/.local/state/starquant/locks/` 的账户锁采用 `fcntl`，仅保护同机同系统用户，Demo 指纹绑定无法识别同账户的另一把密钥。一个账户只由一个项目管理，不支持多机器并发。当前验证环境为 Linux / Python 3.12。

订单身份先持久化，再发送；结果未知时只查原身份，入场或加仓不换 ID 重发。普通成交按原生 `orderId` 归属；条件父单完成后核验 `actualOrderId` 子单，方向和时间相同不足以认领。保护阶段、子单 ID、累计成交和吸收标志一起落盘，账本与游标一起提交。未知保护、撤销或子单阻断新增风险并阻止停机报完成。

条件保护使用 `/fapi/v1/algoOrder`、`closePosition=true`、`CONTRACT_PRICE`；普通市价单使用 `/fapi/v1/order`。先预检两侧触发价，确认止损后才发灾备止盈；替换时确认新止损覆盖，再撤旧保护。归属不明时暂停自动策略出口、反手和策略记忆推进；显式 `flatten` 仍可处理实仓。已确认归属的仓位可补保护，超时裸露则尝试只减仓。

每轮写 `journal.jsonl` 并轮转；跨 UTC 日首次完成轮次用 SQLite online backup 保存一致性副本，保留最近七份。备份失败会提示，不自动跨磁盘保存。完整状态与备份须保存在仓库外；不要删除 SQLite、环境标记或意图来建立“新账户”。

## 排障与恢复

| 输出或情况 | 处理 |
| --- | --- |
| 缺少密钥 / UID 不一致 | 核对环境变量与本人账户；保留原状态，不能用另一目录绕过绑定 |
| 行情缺口、滞后或预热不足 | 核对分钟连续性与完整小时窗口，等待有效行情；`check` 成功不证明可以产生信号 |
| `stop.request` / `flatten.request` 存在 | 核对前次收尾的实仓、保护和剩余项，再用 `resume` 清除请求 |
| 原订单查不到或结果未知 | 先核对交易所订单记录；仅在明确不存在时使用对应原编号的 `resolve --yes`，不能换编号重发 |
| 实仓归属不明 | 核对外部程序与账户记录；需要管理当前实仓时显式 `takeover`，需要清仓时显式 `flatten` |
| SQLite 完整性或阶段校验失败 | 保存原文件和完整状态，核对最近有效备份及交易所事实；不以空库替换来恢复交易 |
| 超过近七日 / 最近 1000 条未覆盖游标 | 对照交易所完整对账单和有效备份，恢复原峰值、资金锁、未决意图及游标；无法证明覆盖时保持冻结 |

人工接管后仍同步部分减仓与全平。满足空仓、无活动订单、无未决意图或未结算保护、历史覆盖条件后，第一次 `rearm --yes` 解除接管，**保留回撤峰值与资金锁**。未处于人工接管时，该命令会把回撤基准设为当前权益，解除回撤与资金划转冻结，等于接受此前亏损为新起点；累计绩效峰值保留。

`takeover` 不补造历史，`rearm` 不跳过覆盖缺口。当前没有任意历史导入或强制跳过命令。无法证明旧事实时保持冻结，并由本人在交易所核对和处理风险。
